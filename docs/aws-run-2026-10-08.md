# Real AWS run, 2026-10-08

Run from a laptop against an OpenSearch Serverless **NextGen** `VECTORSEARCH` collection in
`us-east-1`, with Titan Text Embeddings V2 (1024 dims). Same 51 docs, same 15 queries, same
vectors in both stores. Everything was torn down afterwards (`infra/teardown.sh` run twice).

## What we learned that the code could not tell us beforehand

1. **`--standby-replicas DISABLED` is rejected for NextGen groups** (`ValidationException`).
   `create_collection.sh` now uses `ENABLED`.
2. **The explicit `engine: faiss` mapping is rejected on NextGen** (`Field parameter 'engine'
   is not supported`). Notebook 02 falls back to the simplified mapping. The collection then
   reports `engine: faiss`, `name: hnsw`, `mode: on_disk`, `compression_level: 32x` on its own.
3. **SigV4 with service `aoss` works** against the new `*.aoss.<region>.on.aws` endpoint.
4. **The server-side `hybrid` query with a `normalization-processor` search pipeline works**
   on NextGen Serverless.
5. **k-NN in OpenSearch returned the same top-3 order as Chroma for 15/15 queries.**
6. **First request after creation took 2.0 s**, not the 10 to 30 s AWS documents for waking from zero.
   We did not wait 10 idle minutes to measure a true wake-up from scale-to-zero.
7. **With Titan V2, pure vector search reached recall@3 = 1.00 on all three query kinds**, including
   exact error codes. BM25 alone scored 0.00 on the semantic queries. On this small, easy
   dataset hybrid did not beat k-NN in recall.

## Benchmark (`python benchmark.py --repeats 20 --warmup 2`)

OpenSearch latency includes the network round trip from the laptop to `us-east-1`;
Chroma runs in-process. The two are not like-for-like.

| mode                         | kind     |   queries |   p50 ms |   p95 ms |   recall@3 |
|------------------------------|----------|-----------|----------|----------|------------|
| chroma / k-NN                | all      |        15 |     1.31 |     3.8  |       1    |
| opensearch / BM25            | all      |        15 |   169.26 |   185.26 |       0.67 |
| opensearch / k-NN            | all      |        15 |   168.11 |   195.8  |       1    |
| opensearch / hybrid (server) | all      |        15 |   166.99 |   183.03 |       1    |
| opensearch / hybrid (client) | all      |        15 |   326.17 |   339.58 |       1    |

BM25 recall@3 by kind: keyword 1.00, semantic 0.00, mixed 1.00.
Client-side hybrid costs two round trips, so it takes about twice the server-side time.
